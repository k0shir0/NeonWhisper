CORS Misconfiguration + Public Enumeration = NeonWhisper

📅 2026-07-29 ✍️ Blue Team Researcher 🔴 CRITICAL 🕐 ~8 min read

📋 Executive Summary

A forms.services.thrillshare.com endpoint exhibits three compounding flaws: permissive CORS (Access-Control-Allow-Origin: *), missing authentication on POST, and a publicly accessible form structure endpoint. Together they allow an attacker to enumerate every required field and then spam the form from any origin.

⚠️ Impact: A single HTML file (hosted on GitHub Pages, Neocities, etc.) can auto‑submit unlimited fake entries at 1–20 req/s using the visitor's browser as a relay.

🔬 Core Vulnerabilities

1. CORS Wildcard on State‑Changing Endpoint

access-control-allow-origin: *
access-control-allow-methods: GET, POST, OPTIONS, PUT, PATCH, DELETE

Any website can make cross‑origin AJAX requests. The Same‑Origin Policy is effectively disabled.

2. Unauthenticated POST Acceptance

// No token, no CAPTCHA, no CSRF protection
        POST /api/v1/forms/eb94f34b.../responses
        → 201 Created with a new response ID

Submissions are accepted without any authentication or rate limiting.

3. Public Form Element Enumeration (BONUS)

The endpoint /api/v1/forms/9353/elements?include=element_choices... returns the complete form schema (element IDs, types, and choice IDs) without any authentication. This allows an attacker to dynamically build perfectly valid payloads without any prior knowledge. 

curl -X GET "https://forms.services.thrillshare.com/api/v1/forms/9353/elements?include=element_choices&secondary_organization_id=14296"

🛠️ Required Remediation

  1. Restrict CORS origins – replace * with the exact trusted domain.
  2. Add server‑side CAPTCHA validation (reCAPTCHA v3 + backend verification).
  3. Implement IP‑based rate limiting (e.g., 5 submissions per hour, return 429).
  4. Protect the elements endpoint – it must not disclose form structure without authentication.
